## 📌 Executive Summary

**BioWriter Studio** is an intelligent academic writing environment and pedagogical platform engineered specifically for biotechnology undergraduate students, course instructors, and evaluation committees.

Writing a fundable, publication-grade biotechnology research proposal is notoriously difficult. Students frequently struggle with:
1. Translating dense journal papers into actionable research questions.
2. Avoiding the **Thesaurus Swap Trap** and accidental plagiarism.
3. Structuring a rigorous **4-Tier Background Funnel** that establishes an undeniable knowledge gap.
4. Designing **independent, non-contingent Specific Objectives** that avoid catastrophic "domino collapse."
5. Writing experimental methodologies strictly in the **future tense** with essential positive, negative, and vehicle controls.
6. Aligning biotechnology research with realistic risk mitigation (FMEA), biosafety levels, and economic feasibility in **Egyptian Pounds (EGP)**.

BioWriter Studio solves this through an interactive **Socratic writing workflow**, automated rubric auditing, and a synchronized **Faculty Evaluation & Viva Defense Suite**.

### 1. The 4-Anchor Scientific Title Formula
Eliminates vague, unscientific titles. Every title must satisfy:
$$\text{Title} = [\text{Molecular Mechanism}] \text{ in } [\text{Chassis/Organism}] \text{ to } [\text{Quantified Metric}] \text{ for } [\text{Applied Challenge}]$$
*Example*: *"CRISPR-Cas12a Trans-Cleavage Assay in Human Clinical Isolates to Achieve 10 pM Limit of Detection for Rapid Diagnosis of Colistin-Resistant mcr-1 Pathogens."*

### 2. The 4-Tier Inverted Background Funnel (Section 2)
Guides students from global reality down to a precise molecular hypothesis:
- **Tier 1 (Global/National Burden)**: Empirical, quantified statistics (mortality, crop losses, metric tons, economic burden in USD/EGP).
- **Tier 2 (Current State-of-the-Art)**: Existing technological solutions and why they are insufficient.
- **Tier 3 (Biophysical Knowledge Gap)**: The exact biological or chemical bottleneck that remains unaddressed.
- **Tier 4 (Mechanistic Hypothesis)**: *"We hypothesize that [intervention] will [effect] because [specific biochemical rationale]."*

### 3. Decoupled Specific Aims & Domino Collapse Prevention (Section 3)
Reviewers reject proposals if Aim 2 depends on Aim 1 succeeding with 100% yield. BioWriter Studio forces all three Specific Objectives to operate independently:
- **Objective 1**: Computational / Molecular Design & In Silico Validation.
- **Objective 2**: Expression, Optimization & Functional Prototyping.
- **Objective 3**: Analytical Validation, Limit of Detection (LOD), or Field Efficacy.
*Each objective must terminate in an unambiguous, measurable **Go/No-Go Milestone**.*

### 4. Future Tense Guardian & Controls Checklist (Section 4)
- **Rubric 11 Compliance**: Proposals describe work that *will* happen. Writing in the past tense (*"was inoculated"*) triggers a -1.0 mark penalty. The studio audits tense dynamically.
- **Tri-Fold Controls**: Mandates explicit **Positive Controls**, **Negative Controls**, and **Vehicle/Solvent Controls** for all experimental protocols.

### 5. Biotechnology Risk Matrix & FMEA (Section 5)
Students must perform a Failure Mode and Effects Analysis (FMEA) identifying biological failure points (e.g., inclusion body formation, off-target editing, plasmid loss), probability/severity ratings, and parallel fallback strategies.

### 6. Strategy & EGP Budget Engine (Sections 6–9)
- **Ansoff Growth Matrix**: Market Penetration vs. Product Development vs. Market Development vs. Diversification.
- **SWOT & PESTEL**: Strategic biological audit (Political, Economic, Social, Technological, Environmental, Legal).
- **Egyptian Pound (EGP) Milestone Budget**: Itemizes consumables, equipment, diagnostic kits, and automatically calculates institutional overhead (15% indirect costs).

| # | Criterion | Weight | Key Standard Verified |

| **02** | **Structured Abstract** | 1.0 pts | 150–250 words, balanced across Background, Aims, Methods, and Impact. |
| **03** | **Background Funnel** | 1.5 pts | 4-tier inverted funnel with empirical statistics and explicit biophysical gap. |
| **04** | **Decoupled Aims** | 1.5 pts | 3 non-contingent work packages with clear Go/No-Go quantitative milestones. |
| **05** | **Methodology & Controls**| 1.5 pts | Strict future tense protocols with positive, negative, and vehicle controls. |

## 🛠️ Technology Stack & Architecture

- **Frontend Core**:
  - Semantic HTML5 structure with zero third-party bloated CSS frameworks.
  - Custom responsive design system with CSS Grid, Flexbox, and fluid typography.
  - Vanilla JavaScript (ES6+) with reactive state management, debounced auto-sync, and client-side failover.
- **Backend & Governed Agent Architecture**:
  - Lightweight Python Flask application (`app.py`) + Governed Research Workflow Agent (`agent/`).
  - Salted PBKDF2-SHA256 password hashing via Werkzeug Security.
  - Anti-brute-force rate limiting and session state management.
  - Native document exporters generating Microsoft Word (`.docx`), PowerPoint (`.pptx`), and Markdown (`.md`).
- **Offline (`file://` / GitHub Pages) & Cloud Dual-Mode**:
  - Works **100% standalone** on GitHub Pages or by opening `index.html` / `faculty.html` directly in a browser (powered by a built-in client-side `localStorage` Cohort, Team Workspace, and Evaluation Engine).
  - When hosted on Render/Railway/Docker or run locally via Python Flask (`run_portal.bat` / `python app.py`), it activates server-side persistence, live PubMed/Europe PMC evidence retrieval, and multi-device cohort synchronization.

## 🚀 Quick Launch & Deployment

### Option A: GitHub Pages (Static / Zero-Config)
1. Upload the contents of this repository to GitHub.
2. Enable **GitHub Pages** from the root (`/`) of your repository branch.
3. Access the Student Portal at `index.html` and the Faculty Portal at `faculty.html`.

### Option B: Running the Full Python Flask Server Locally or in the Cloud
1. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
2. Start the server:
   - **Windows**: Double-click **`run_portal.bat`**
   - **Cross-Platform**: Run `python app.py`
3. Open `http://127.0.0.1:5000` (Student Portal) or `http://127.0.0.1:5000/faculty` (Faculty Portal).
